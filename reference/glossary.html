ACP Glossary

Canonical terms taught so far. Added only after a lesson teaches them.

Terms

ACP (Agent Client Protocol)
JSON-RPC 2.0 protocol that standardizes communication between a code editor (Client) and a coding agent (Agent).
Client
The editor/IDE side of ACP. Owns UX, files, editor state, and permissions display.
Avoid: server, frontend
Agent
The AI side of ACP. Owns reasoning, planning, and tool-call decisions; asks the Client to apply edits.
Avoid: model, LLM, backend
Session
A task-scoped conversation opened by session/new, identified by a sessionId. The Agent keeps its history; the Client keeps the id.
Avoid: connection, socket
session/update
Agent-to-Client notification streaming progress (messages, state, tool activity) after a session/prompt ack.
Traffic Light (running / requires_action / idle)
The Agent's foreground state, reported via state_update. Prompt only on green (idle); answer amber (requires_action); wait on red (running).
Capability
Something one side advertises in initialize (prompt types, MCP transports, auth methods). Requests outside the list are denied, never attempted.
MCP server
An external tool server the Agent connects to for a session, listed at session/new. Usable only if its transport was also advertised as a capability.
Connection
The transport carrying bytes (stdio pipe or HTTP). Disposable: drops kill it, and the Client opens a new one and resumes.
Avoid: session (the town, not the road)
Outbox
Client-side queue holding prompts typed while the road is down, flushed in order on reconnect.
Slash command
An Agent-advertised shortcut fired as /name args prompt text. Ordered only off the posted menu.
