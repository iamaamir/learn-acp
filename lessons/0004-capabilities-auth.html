The Guest List: Capabilities, Auth & Permissions

Promise: you will predict allow / deny / ask for any request before sending it.

Framing: the bouncer

Last time you played the Client answering amber. But who decided the Agent could ask — and why did the answer travel as a permission instead of a prompt? Because of the envelope from Lesson 0001: initialize trades guest lists. The Agent advertises prompt content types (image, audio), MCP transports (stdio, http), and authMethods. The Client picks servers at session/new. After that, the bouncer enforces the list: on it → allow, not on it → deny, edits → ask the host (requires_action).

Memorable label: “The Guest List” — negotiated once, enforced every turn.

Hands-on exercise (real code, 10 min)

  1. Run node --test from the course root. All 17 tests should pass.
  2. Play bouncer in node: 
    import {
  canSendPrompt, canUseMcp, gate,
} from './src/acp-capabilities.mjs';
const caps = { session: { prompt: { image: {} }, mcp: { stdio: {} } } };
console.log(canSendPrompt(caps, ['text', 'image'])); // ok
console.log(canSendPrompt(caps, ['audio']));         // missing audio
const http = [{ type: 'http' }];
console.log(canUseMcp(caps, http, 'http')); // false — unadvertised
console.log(gate({ kind: 'edit' }));                 // ask, always

Payoff

Interview Q: “An image prompt fails. Walk me through the debugging.”

Model answer: “First I read the snapshot of agentCapabilities from initialize — is session.prompt.image there? If not, it’s not a bug, it’s the guest list: fail fast with ‘needs prompt:image, negotiated vN without it’. If it is there, I check the block I sent and the session state — and for tool failures I check both the advertised MCP transport and whether session/new actually connected a server of that type. Never assume; branch on the negotiated list.”

Pro tip (production): snapshot the negotiated capabilities per session next to the sessionId, and re-fetch on every reconnect. Stale caps after an Agent upgrade are the classic ‘worked yesterday’ mystery — the list changed under you.

With this, you can now build: a client that greys out unsupported inputs (no audio button when unadvertised) instead of letting users hit a wall.
