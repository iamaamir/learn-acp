The Stream: Prompt Lifecycle

Promise: you will know exactly when a prompt may be sent — and what to render while it can’t.

Framing: the traffic light

Last time we blurred session/update into “a stream.” Now open it up. Every prompt runs a tiny traffic light on the Agent: green (idle — send!), red (running — wait), amber (requires_action — the Agent is holding at the line, answer it, don’t send a new prompt). In v2 the Agent acks your session/prompt immediately and everything after arrives as session/update notifications — including the light changes themselves.

Memorable label: “The Traffic Light” — prompt on green, wait on red, answer amber.

The three lights and what your UI owes each
Light Meaning Client must
running foreground work in flight stream updates, disable the send box (or queue)
requires_action blocked on the user (e.g. permission) render the decision UI, reply grant/deny — not a new prompt
idle turn over, stop reason attached re-enable send; log the stop reason

Hands-on exercise (real code, 10 min)

  1. Run node --test from the course root. All 9 tests should pass.
  2. Enforce the light in node: 
    import { transition, canPrompt } from './src/acp-lifecycle.mjs';
let s = 'idle';
s = transition(s, 'session/prompt');   // running
console.log(canPrompt(s));             // false — send box stays shut
s = transition(s, 'state:requires_action');
try {
  transition(s, 'session/prompt');
} catch (e) {
  console.log(e.message);
}
s = transition(s, 'permission:grant'); // running again
s = transition(s, 'state:idle');       // idle — green light
  3. Stretch (prompt queue): write a queuePrompt(state, box, text) helper — if canPrompt(state) send now, else push to box and flush on state:idle. Test: two rapid prompts during running go out in order after the turn completes.

Payoff

Interview Q: “When is it safe to send the next prompt, and how do you know?”

Model answer: “Only in idle. I track the Agent’s state_update notifications — running means a turn is in flight, so I disable send or queue; requires_action means the Agent is blocked on me, so I render the permission decision and answer that instead of prompting; idle carries the stop reason and re-arms the send box. Sending mid-turn isn’t a second turn — it’s a protocol error or a lost message, depending on the Agent.”

Pro tip (production): put a timeout with default-deny on every requires_action, and log every stop reason (complete vs cancelled vs error). “Stuck session” bugs are almost always a swallowed amber light or an ignored stop reason.

With this, you can now build: a send box that can’t misfire — green on idle, queued on red, decision UI on amber.
