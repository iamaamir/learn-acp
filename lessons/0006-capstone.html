The solo: build it in node (acceptance spec)

Rehearsal was training wheels. Now fly without them — extend the course modules until all five hold. Suggested shape (yours to design): a loop() reading stdin, wired to SessionStore + Link + the guards.

  1. Persists the handle. Save {sessionId, cwd, caps} to a file on every prompt; restart the process and resume — no new session.
  2. Guards the light. Prompts sent while !canPrompt(state) are queued, never fired. Prove it with a test.
  3. Works the list. An audio block with unadvertised caps fails before any wire traffic, naming need vs have.
  4. Answers amber. An edit surfaces a real yes/no decision; timeouts default to deny.
  5. Rides the drop. Kill the link mid-turn: outbox queues, reconnect resumes the same id, flush order preserved — covered by a test like the ones in tests/acp-transport.test.mjs.

Done when all five hold and node --test is green. That is the mission in MISSION.md, landed.

Payoff

Interview rapid-fire (one per lesson):

Why not embed the agent? M×N integrations; split thinking from acting. — Where does state live? Agent holds history, Client holds the id. — When may you prompt? Only on idle; answer amber first. — Image prompt fails? Read the negotiated caps before the wire. — Drop mid-turn? New road, same town: resume, flush, cancel-and-retry.

Pro tip (beyond the course): the protocol moves — pin your implementation to a negotiated version (Lesson 0001's handshake) and re-read the RFDs quarterly. Version skew is the tavern rumor of agent bugs: always suspected, rarely proven, often guilty.
