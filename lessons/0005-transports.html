The Road: Transports & Drops

Promise: you will say exactly what survives a dropped connection — and how to come back.

Framing: the road vs the town

Every lesson so far rode an invisible road. Time to look at it. The connection is the road — a stdio pipe to a local subprocess, or Streamable HTTP (POST /acp with connection/session headers) to a remote agent. The session is the town — history, capabilities, the tab — living on the Agent. Washouts close roads. Towns stand. Recovery is therefore always the same shape: reconnect, resume the session, flush what queued, cancel or retry the turn that was mid-flight (session/resume, then session/cancel + re-prompt if needed).

Memorable label: “The Road” — connections are disposable, sessions are durable. Never mint a new session when the old id still exists.

Hands-on exercise (real code, 10 min)

  1. Run node --test from the course root. All tests should pass.
  2. Drop the road in node: 
    import { Link } from './src/acp-transport.mjs';
const link = new Link();
link.connect('http');
const id = link.agent.open('/proj');
link.send(id, 'one');   // sent
link.drop();
link.send(id, 'two');   // queued, road down
console.log(link.reconnect(id)); // resumed + flushed
  3. Stretch (heartbeat): write a watchdog(link, id, beats) that counts missed heartbeats and calls reconnect after 3 misses — but only if the session still exists. Test the gone-session path throws toward session/new.

Payoff

Interview Q: “The connection drops mid-turn. What breaks, what survives, how do you recover?”

Model answer: “In-flight bytes and the streaming cursor die with the connection; the session — history, capabilities, the tab — survives on the Agent. Recovery: reconnect on either transport, session/resume with the saved id, flush the client outbox in order, then settle the interrupted turn — session/cancel and an idempotent re-prompt, since I can't know what the Agent finished. And I never open a fresh session while the old id exists — that's how you orphan tabs.”

Pro tip (production): heartbeat the connection and rotate connection ids freely — they're disposable. Treat every send as at-least-once: attach an idempotency key per prompt so a flushed retry can never double-apply an edit.
