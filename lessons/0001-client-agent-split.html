The Split: Client vs Agent

Promise: you will explain why ACP exists and who owns what — without hand-waving.

Framing: USB-C for coding agents

Before USB-C, every phone needed its own cable. Before ACP, every editor needed a custom integration for every agent — an M×N mess. ACP is the USB-C: one JSON-RPC 2.0 plug so any Client (editor/IDE) works with any Agent (AI coder).

Memorable label: “The Split” — the Agent thinks, the Client acts. The wire between them is ACP.

    }
  }
}

Payoff

Interview Q: “Why not just embed the agent in the editor?”

Model answer: “Embedding gives M×N integrations and locks capability checks, auth, and permission UX into each pair. ACP splits concerns: the Agent owns reasoning and tool decisions, the Client owns files and user consent. Capabilities are negotiated once in initialize, so a Client never calls a method the Agent doesn’t support — same reason LSP beat per-editor language plugins.”

Pro tip (production): always branch on the negotiated agentCapabilities before calling session/*. Agents differ (image/audio context, MCP stdio vs http). Fail with “agent doesn’t support X, negotiated vN” — not a cryptic method-not-found.
